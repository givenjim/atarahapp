# Atarah — API

Implemented in P0-M3. Endpoints are added per module; the OpenAPI document is always generated from the code.

## Conventions

- Base path `/api/v1`; admin under `/api/v1/admin/*`; webhooks under `/api/v1/webhooks/{provider}`. Health probes are the exception: `/health/live`, `/health/ready` (DEC-011).
- Success: `{ "data": ..., "meta": { ... } }`. Collections: `meta: { page, limit, total }` (offset) or `meta: { nextCursor, limit }` (feeds). Default `limit` 20, maximum 100.
- Error: `{ "error": { "code", "message", "details", "requestId" } }`. Codes: `AUTHENTICATION_REQUIRED`, `INVALID_CREDENTIALS`, `FORBIDDEN`, `PREMIUM_REQUIRED`, `VERIFICATION_REQUIRED`, `APPROVAL_REQUIRED`, `RESOURCE_NOT_FOUND`, `VALIDATION_ERROR`, `CONFLICT`, `INVALID_STATE`, `RATE_LIMITED`, `PAYMENT_ERROR`, `EXTERNAL_SERVICE_ERROR`, `INTERNAL_ERROR`. Unexpected errors are always `INTERNAL_ERROR` with a generic message; internals are logged against the `requestId`.
- `VALIDATION_ERROR` carries `details.fields: [{ field, messages[] }]`. Unknown request properties are rejected.
- Send `X-Request-Id` (8–64 chars of `A-Za-z0-9._-`) to correlate; otherwise the server generates one. It is echoed in the response header and the error body.
- Sorting uses a per-resource whitelist of `recent | deadline | relevance | popularity | rating | price`; anything else is `VALIDATION_ERROR`.
- `Idempotency-Key` is required on payment initiation, booking creation, membership upgrade, opportunity submission and enrolment (implemented with those endpoints).

## Building blocks (apps/backend/src/common)

`ApiException` (throw this from domain code), `AllExceptionsFilter`, `ResponseEnvelopeInterceptor` + `Paged`, `createValidationPipe`, `PageQueryDto` / `CursorQueryDto` / `cursorPage`, `resolveSort`.

## OpenAPI

- Swagger UI: `http://localhost:3000/api/docs` (not served in production). JSON: `/api/docs/openapi.json`.
- Regenerate the committed contract: `pnpm gen:api` → `packages/api-contracts/openapi.json` (no database needed).
- Documented paths: see `packages/api-contracts/openapi.json`. Health is hidden from Swagger by design.

## Auth (Supabase Auth, P1-M6)

Sign-up, one-time-code verification, sign-in, token refresh, password recovery, MFA and Google sign-in are **not** NestJS endpoints any more: the apps call Supabase Auth directly (`supabase_flutter` on mobile, `@supabase/ssr` on web and admin). The access token Supabase returns is the bearer for this API: `Authorization: Bearer <access_token>`. Responses use the standard envelope.

| Method and path                     | Auth                                             | Notes                                                                                                                                      |
| ----------------------------------- | ------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `GET /users/me`                     | Bearer (pending accounts allowed)                | The account, roles, entitlements, membership summary and preferences (`appearance`, `locale`, `timeZone`, `marketingOptIn`)                |
| `GET /me/preferences`               | Bearer                                           | `{ appearance, locale, timeZone, marketingOptIn }`; defaults when the member has no row yet (created on first read)                        |
| `PATCH /me/preferences`             | Bearer                                           | Partial update of the same four fields. `appearance` is `LIGHT` or `DARK`; `timeZone` an IANA name; `locale` a language tag. Own row only. |
| `GET /me/security`                  | Bearer                                           | `{ factors[], twoStepEnabled, activeSessions }` (MFA factors enrolled in Supabase Auth)                                                    |
| `PUT /me/device`                    | Bearer                                           | `{ deviceHash, name, platform }` → `{ newDevice }`. Called after every sign-in; links the device to the session                            |
| `GET /auth/sessions`                | Bearer                                           | Active sessions (`id` = Supabase session id, `client`, `deviceName`, `lastActiveAt`, `current`)                                            |
| `DELETE /auth/sessions/{id}`        | Bearer                                           | Signs that session out at once. 404 for someone else's session                                                                             |
| `POST /auth/sessions/revoke-others` | Bearer                                           | Keeps the current session, ends the rest → `{ sessionsRevoked }`                                                                           |
| `POST /auth/hooks/send-sms`         | Supabase Auth hook (Standard Webhooks signature) | Not for apps; hidden from OpenAPI. Sends the sign-up / sign-in code through the SMS provider adapter                                       |

**Sign-up metadata the app sends to Supabase** (`data`): `full_name`, `terms_version`, `privacy_version`. A database trigger turns them into the `users` row and the consent records.

**Admin (`/admin/*`)**

| Method and path      | Auth                | Notes                                          |
| -------------------- | ------------------- | ---------------------------------------------- |
| `GET /admin/auth/me` | Admin bearer (AAL2) | User view plus `permissions[]` for the sidebar |

Every `/admin/*` request needs a staff account **at AAL2** (a verified TOTP factor). The console signs in with Supabase Auth, then enrols or verifies a TOTP factor; sensitive actions need the factor verified within the last 5 minutes.

**Denial responses clients must handle**

| Situation                      | Status / code                 | `details`                                                                        |
| ------------------------------ | ----------------------------- | -------------------------------------------------------------------------------- |
| No or invalid token            | 401 `AUTHENTICATION_REQUIRED` |                                                                                  |
| Admin idle                     | 401 `AUTHENTICATION_REQUIRED` | `reason: SESSION_IDLE`                                                           |
| Sensitive admin action         | 401 `AUTHENTICATION_REQUIRED` | `reason: REAUTH_REQUIRED`                                                        |
| Account not verified           | 403 `VERIFICATION_REQUIRED`   | `reason: ACCOUNT_PENDING_VERIFICATION`                                           |
| Staff without MFA (AAL1)       | 403 `FORBIDDEN`               | `reason: MFA_REQUIRED` (verify the authenticator, then retry with the new token) |
| Member without a staff role    | 403 `FORBIDDEN`               | `reason: ADMIN_ONLY`                                                             |
| Signed-out or revoked session  | 401 `AUTHENTICATION_REQUIRED` | the Supabase session no longer exists                                            |
| Account suspended, deactivated | 403 `FORBIDDEN`               | `reason: ACCOUNT_SUSPENDED`, `ACCOUNT_DEACTIVATED`                               |
| Missing permission             | 403 `FORBIDDEN`               | `missing: [..]`                                                                  |
| Needs Pro                      | 403 `PREMIUM_REQUIRED`        | `entitlement`                                                                    |
| Wrong token type for the route | 403 `FORBIDDEN`               | `reason: ADMIN_ONLY` or `MEMBER_ONLY`                                            |
| Too many attempts              | 429 `RATE_LIMITED`            | `retryAfterSeconds`, `reason: SIGN_IN_LOCKED` (sign-in)                          |

## Community: feed, posts, comments, reactions, groups, connections and safety (P1-M8)

Member bearer token. Permissions: reading needs `community.view`; posting and editing `community.post`; commenting and reacting `community.comment`; saving `saved.manage.own` (all member defaults). Posting, commenting and sending a connection request also need an **ACTIVE account with a verified email or phone** and no standing restriction: otherwise `403 VERIFICATION_REQUIRED` (`details.reason` `CONTACT_NOT_VERIFIED`) or `403 FORBIDDEN` (`ACCOUNT_RESTRICTED`). A post, comment, member or group the caller may not see (audience, group membership, blocks in either direction, status) is `404 RESOURCE_NOT_FOUND`, the same answer as for one that does not exist.

**Cursor pages** (feed, group posts, comments, saved posts): `?limit=1-100&cursor=` and `meta: { nextCursor, limit }`. Feed and group-post cursors are opaque base64url JSON `{ t: rankingTimeIso, id }` ordered by `(t, id)` descending; comment and saved-post cursors are `{ t, id }` by creation time (comments ascending, saved posts descending). Never parse them; a malformed one is `400 VALIDATION_ERROR`. Lists of people, groups, blocks and reports use `?page=&limit=` and answer `meta.total`.

**Error documentation.** Every operation in the OpenAPI document lists the error responses it can give (400, 401, 403, 404, 409, 429 as they apply) with the standard error envelope, an example and `x-error-codes`. They are added to the generated document (`common/openapi-errors.ts`), so a controller does not repeat them.

**Rate limits.** Reads: 120 requests a minute per client. Anything that changes data (POST, PUT, PATCH, DELETE): 60 a minute. Sensitive routes carry a tighter explicit `@Throttle` (`scripts/check-rate-limits.ts` lists them and fails if one is missing).


## Payments (P2-M1)

Amounts are integer minor units (KES cents). A payment's status only ever comes from the server, which only trusts the payment provider. State machine: `INITIATED -> PENDING -> SUCCEEDED | FAILED | CANCELLED`, then `PARTIALLY_REFUNDED | REFUNDED` (DEC-101).

| Method and path                         | Notes                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| --------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /payments/methods`                 | Methods the app may show: M-Pesa when `payments-mpesa` is on and credentials exist; Card only when `card-payments` is on and a provider is connected (not yet).                                                                                                                                                                                                                                                                                                                                                                                         |
| `POST /payments`                        | Starts a payment. Body `purpose`, `referenceId?`, `method`, `phone?` (any Kenyan format, never stored in full), `sandboxAmountMinor?` (only the `OTHER` sandbox purpose). Header **`Idempotency-Key`** (8 to 128 characters) is required. 201 with `action` (`STK_PROMPT` or `REDIRECT`). 409 `CONFLICT` with `details.paymentId` while another payment for the same purchase is open. 503 `PAYMENT_ERROR` when the method is off, 502 `PAYMENT_ERROR` when the provider refuses (the payment is recorded as `FAILED` and the message says what to do). |
| `GET /payments/{id}`                    | The payer's own payment (404 for anyone else). Poll every `pollAfterSeconds`; `timedOut` means the time limit passed and the app offers "Try again" while the server keeps checking.                                                                                                                                                                                                                                                                                                                                                                    |
| `GET /payments`                         | The payer's payments, newest first (receipts).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `POST /webhooks/payments/mpesa/{token}` | Safaricom callback. Public, not in OpenAPI, unguessable token, 404 on a wrong token, answers `{ResultCode: 0}`. A success callback only triggers a status query (DEC-102).                                                                                                                                                                                                                                                                                                                                                                              |
