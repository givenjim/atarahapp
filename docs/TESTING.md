# Atarah — Testing

Placeholder (P0-M1). Expectations are in Master Prompt §7.7.

| Layer       | Tools                                                                                                                 |
| ----------- | --------------------------------------------------------------------------------------------------------------------- |
| Backend     | Jest, Supertest against the **local Supabase stack** (real Auth, Postgres, Storage, Realtime, mail catcher) and Redis |
| Mobile      | flutter_test, golden tests, `integration_test` on the Android emulator                                                |
| Web / admin | Vitest/Jest + Testing Library, Playwright                                                                             |
| Load        | k6                                                                                                                    |

Backend integration tests need `just infra-up` first (Docker running). The global setup reads `supabase status`, applies migrations, sets the backend role password, empties every Auth user and application table and flushes Redis database 15, and refuses any non-local database. Helpers sign in through real Supabase Auth (`makeUser`, `loginMember`, `adminSignIn` with a TOTP factor). Specs: `auth` (sign-up, codes read from the local mail catcher, sign-in, refresh, recovery, sessions, devices, Send SMS hook including a real phone sign-up), `access` (authorisation matrix, admin AAL2, idle timeout, re-authentication), `supabase` (RLS, anon key refused everywhere, Realtime delivery), `ops` (metrics), `media` (Supabase Storage).

Results are recorded here with real numbers. A defect list (bug bash) starts in P3-M7.

flutter analyze            # strict lints (analysis_options.yaml)

## Phase 1 completion audit: how to re-run it (P1-M12)

Run these at the end of every milestone and before the gate. Commands are from the repository root unless noted. Integration tests reset the one local database, and the generators rewrite shared files, so when several people or agents work at once take the lock: `bash apps/backend/scripts/with-lock.sh int <command>` for integration tests and `... gen <command>` for API client generation.

| Audit                                  | Command                                                                                                                                                       | What it proves                                                                                                                                                                                                                      |
| -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Migrations from empty, seed, all tests | `pnpm -r test` (backend: unit then integration; the integration setup resets the database and runs `prisma migrate deploy` from empty, then the reference seed) | Every migration applies to an empty database; every suite passes.                                                                                                                                                                   |
| Migrations on top of a database with data | `bash scripts/db-backup.sh`, then apply the new migrations to that database with `pnpm --filter @atarah/backend db:migrate`                                | Run on a dev database carrying data from every milestone (`pnpm db:seed` plus the showcase script). Nothing destructive is allowed.                                                                                                |
| OpenAPI vs Appendix A                  | `pnpm gen:api` then `cd apps/backend && npx ts-node --transpile-only scripts/check-api-coverage.ts` (add `--final` at the gate)                              | Every Phase 1 endpoint of Appendix A.2 is present, a recorded deviation, or reported (PENDING/MISSING); the generated Dart client knows every operation; prints how many operations document error responses and examples.        |
| Authorisation matrix and IDOR          | `cd apps/backend && bash scripts/with-lock.sh int node --experimental-vm-modules node_modules/jest/bin/jest.js --selectProjects integration --runTestsByPath test/authz-matrix.int-spec.ts` | Every route (read from the controllers' decorators, 288 at the time of writing) as 7 kinds of caller, the role matrix, and IDOR on every `{id}` route that holds member data.                                                        |
| Rate limits                            | `cd apps/backend && npx ts-node --transpile-only scripts/check-rate-limits.ts` (`--all` lists every route)                                                  | Every mutating and search route is limited; sensitive routes have an explicit limit.                                                                                                                                                |
| Supabase posture                       | `node scripts/check-rls.mjs`, `node scripts/check-auth-config.mjs`; `test/hardening.int-spec.ts` (anon key reads nothing)                                    | RLS on every table, no stray policies or grants; local Auth settings against section 5.5 (warnings are platform limits, listed in SECURITY.md).                                                                                     |
| Jobs                                   | `cd apps/backend && npx jest --selectProjects unit src/queues/jobs-audit.spec.ts`; time-travel tests live beside each job (opportunities, community, analytics, account, notifications) | One processor per queue, every scheduled job has a handler, retries with exponential backoff, failed jobs kept for the admin failed-jobs view (`GET /admin/jobs`).                                                                  |
| Performance                            | `node apps/backend/scripts/perf/setup-perf-db.mjs && node apps/backend/scripts/perf/load-volume.mjs && node apps/backend/scripts/perf/run-perf.mjs`         | The volume seed (10,000 members, 50,000 posts, 200,000 comments, 2,000 opportunities, 500 learning items, 100,000 notifications) in the scratch database `atarah_perf`, p95 per hot endpoint, SQL statements per request, EXPLAIN ANALYZE; writes `docs/PERFORMANCE.md`. Run `setup-perf-db.mjs` again after new migrations so the scratch schema matches. |
| Backup and restore                     | `bash scripts/db-backup-test.sh [database]`                                                                                                                  | A dump of the public and auth schemas restores into a scratch database with identical row counts.                                                                                                                                   |
| ER diagram                             | `pnpm --filter @atarah/backend db:erd`                                                                                                                       | Regenerates `docs/DATABASE-ERD.md` from the Prisma schema.                                                                                                                                                                          |
